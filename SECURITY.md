# Security Policy

## Supported surface

Security fixes target the current default branch unless a maintained release is explicitly documented.

## Reporting a vulnerability

Do not publish exploit details, credentials, private data, or proof-of-concept material in a public issue.

If GitHub shows a **Report a vulnerability** control for this repository, use that private channel. If it is unavailable, open a public issue titled `Security contact requested` containing only enough non-sensitive information to request a private reporting path.

For an accidentally committed credential, revoke or rotate it first; removing it from a later commit does not make the exposed value safe again.

## Scope

Security reports should identify the affected repository/ref, the security boundary involved, and the smallest reproducible impact that can be shared safely.
